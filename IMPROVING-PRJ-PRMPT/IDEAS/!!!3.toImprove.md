# Handoff: make per-task red-verify required only for T3

## Problem

Current workflow treats per-task `/red-verify` as required for both `T2` and
`T3` task closure.

This is too heavy for normal `T2` work. `T2` still needs semantic review, but
the useful check is usually feature-level after all tasks for that feature are
implemented, not a separate adversarial pass for every task.

## Target policy

- `T0` / `T1`: no required `/red-verify`.
- `T2`: no required per-task `/red-verify` for task closure.
- `T2`: feature-level semantic red-verify is required after the feature
  implementation is complete and before the feature is treated as complete.
- `T3`: per-task `/red-verify` remains required before task closure.
- `T3`: exact human/recovery markers remain required:
  - `HUMAN_CHECKPOINT: done`
  - `ROLLBACK_RECOVERY_NOTE: present`

Task lifecycle stays unchanged:

```text
planned|ready|in_progress|blocked|done|failed
```

## Closure rules

Task closure:

```text
T0/T1: tier-appropriate evidence / verify policy
T2: full protocol + /verify PASS + required packet/spec gates
T3: full protocol + /verify PASS + per-task /red-verify semantic-pass + human/recovery markers
```

Feature closure:

```text
T2 feature: feature-level semantic red-verify must pass after feature implementation
T3 tasks: already require per-task red-verify before task closure
```

Do not make `T2` task closure depend on per-task `SEMANTIC_VERDICT`.

## KISS design for feature-level red-verify

Do not add a new command or artifact family.

Extend existing `/red-verify` docs/skill to support modes:

```text
/red-verify TASK-123       # per-task; required only for T3, optional for T2
/red-verify --feature FT-001  # feature-level semantic review after T2 feature implementation
```

Recommended evidence locations:

```text
.tasks/FT-001/FT-001-S-RED-VERIFY-final-report-docs-01.md
```

Keep this as feature-completion policy. Do not make `mb-doctor --strict` block
every intermediate task selection on a missing feature-level artifact.
